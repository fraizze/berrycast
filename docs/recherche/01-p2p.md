### Modes de la puce (`iw list`)

Modes : `managed`, `AP`, `P2P-client`, `P2P-GO`, `P2P-device`.

Combinaisons possibles **en même temps** :

```
#{ managed } <= 2, #{ P2P-device } <= 1, #{ P2P-client, P2P-GO } <= 1, total <= 3, #channels <= 2
#{ managed } <= 1, #{ AP } <= 1, #{ P2P-client } <= 1, #{ P2P-device } <= 1, total <= 4, #channels <= 1
```

**Conclusion** : la puce **annonce** la connexion au Wi-Fi de la maison (`managed`) **en même
temps** qu'un groupe Wi-Fi Direct (`P2P-GO` ou `P2P-client`), et même sur **deux canaux différents**
(`#channels <= 2`). C'est ce dont Miracast a besoin. À confirmer en pratique (étape 03) : ce que
le pilote annonce ne marche pas toujours parfaitement sur cette puce.

Un « P2P Device » dédié existe déjà (`iw dev` : interface sans nom de type `P2P-device`).

## 2. Choix technique : API D-Bus de wpa_supplicant

- On pilote le Wi-Fi Direct **directement par l'API D-Bus de wpa_supplicant**, sans modifier
  la configuration de NetworkManager : la connexion au Wi-Fi de la maison n'est pas touchée.
- NetworkManager sait faire du Wi-Fi Direct, mais seulement comme **source** (il se connecte à un
  écran) ; il ne sait pas **attendre et accepter** une connexion comme un écran Miracast.
- Point vérifié dans le code source de wpa_supplicant : avec un « P2P Device » dédié, l'interface
  interne `p2p-dev-wlan0` **n'a pas d'objet D-Bus à elle** ; l'API `Interface.P2PDevice` et ses
  signaux passent par l'objet D-Bus de **wlan0**. (Le diagnostic l'avait marquée « absente » :
  probablement une limite de `busctl introspect` ; le prototype le vérifie directement.)
- Risque connu : NetworkManager gère aussi `p2p-dev-wlan0`. S'il efface nos éléments Wi-Fi
  Display, le prototype les remet (vérification toutes les 30 s). Si NetworkManager gêne à
  l'étape 03, piste : `nmcli device set p2p-dev-wlan0 managed no`.

### Données publiées

- Nom Wi-Fi Direct : `BerryCast-Test`.
- Type d'appareil WPS : `0007 0050F204 0001` = écran (catégorie 7), télévision (sous-catégorie 1).
- Éléments Wi-Fi Display (propriété `WFDIEs`) : `00 0006 0011 1c44 0032`
  - `00` : sous-élément « WFD Device Information », longueur `0006` ;
  - `0011` : récepteur principal (bits 0-1 = 01) + session disponible (bit 4) ;
  - `1c44` : port RTSP 7236 ; `0032` : débit maximal 50 Mb/s.

### Sources

- Code source de wpa_supplicant (paquet Debian `wpa`) : `wifi_display.c`
  (`wifi_display_subelem_set_from_ies`), `dbus/dbus_new_handlers_p2p.c`
  (`wpas_dbus_setter_global_wfd_ies`, `P2PDeviceConfig`), `wpa_supplicant.c` et `dbus/dbus_new.c`
  (P2P Device dédié), `src/wps/wps_defs.h` (types d'appareils).
- Documentation D-Bus : <https://w1.fi/wpa_supplicant/devel/dbus.html> (méthodes `Find`,
  `Listen`, signaux `DeviceFound`, `GONegotiationRequest`, `ProvisionDiscovery…`).
- Bits « WFD Device Information » : Android AOSP `WifiP2pWfdInfo.java`.
